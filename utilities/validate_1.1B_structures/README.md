# HydraGNN Inference — Structure Validation Pipeline

## Overview

This pipeline validates atomistic structures generated by large-scale HydraGNN
fused inference on Frontier (OLCF). Starting from ~1.1 billion structures stored
in ADIOS2 BP5 format, it filters for physically valid and potentially synthesizable
candidates using a two-stage MPI-parallel validation sweep.

**Compute context**
- Inference run: 9,300 nodes on Frontier (`lrn070` allocation)
- Structures generated: ~1.1 billion (9,300 BP5 files × 120,000 structures/file)
- Storage format: one BP5 directory per tar file, on Lustre (`/lustre/orion/`)
- Validation run: 40 nodes on Andes (1,280 MPI ranks, ~7 files/rank)
- Result: ~500,000 synthesizable candidate structures

## Pipeline Architecture

```
Lustre (9,300 .tar files)
        │
        │  round-robin across 1,280 MPI ranks
        │  (~7 tar files per rank)
        ▼
┌─────────────────────────────────┐
│  Per rank:                      │
│  1. extract .tar → /tmp         │  node-local NVMe, avoids Lustre metadata
│  2. open BP5 with adios2        │  step-by-step (1 structure = 1 ADIOS step)
│  3. Stage 1: physical checks    │  energy → forces → min distance
│  4. Stage 2: synth checks       │  elements → bonding → valence → radicals
│  5. cleanup /tmp                │  free space before next tar
│  6. write rank .npz to Lustre   │
└─────────────────────────────────┘
        │
        ▼
aggregate_validation.py          # combines 1,280 .npz files into global summary
```

## Data Format

Each BP5 file contains 120,000 ADIOS2 steps. Each step is one structure:

| Variable           | Shape  | Type    | Description                        |
|--------------------|--------|---------|------------------------------------|
| `atom_types`       | `{N}`  | int32   | Atomic numbers (Z) per atom        |
| `coordinates_x/y/z`| `{N}` | float64 | Atomic positions in Å              |
| `forces_x/y/z`    | `{N}`  | float64 | Predicted forces in eV/Å           |
| `formation_energy` | `{1}`  | float64 | Predicted formation energy in eV   |

`{N}` is variable-length per step (different structures have different atom counts).
No lattice vectors are stored — structures are treated as non-periodic.

---

## Validation Checks

Checks are applied as a fast-to-slow gate. A structure that fails Stage 1
never reaches Stage 2.

### Stage 1 — Physical Validity

| Check | Threshold | Catches |
|---|---|---|
| Formation energy finite + in range | −20 to +20 eV | NaN/Inf predictions, garbage outputs |
| Force magnitude finite + bounded | ≤ 50 eV/Å | Unphysical geometries |
| Min interatomic distance | ≥ 0.5 Å | Atom overlaps from inference artifacts |

### Stage 2 — Synthesizability

Applied only to Stage 1 survivors. Uses element-specific covalent radii
(Alvarez 2008, DOI 10.1039/b801115j) to determine bonding.

| Check | Detail | Catches |
|---|---|---|
| Element whitelist | Z ∈ 1..83, excluding Tc (43) and Pm (61) | No stable isotopes → not synthesizable |
| No isolated atoms | Every atom has ≥ 1 neighbor within `r_i + r_j + 0.4 Å` | Disconnected fragments |
| Valence not exceeded | Bond count ≤ `MAX_VALENCE[Z]` per atom | Impossible bonding (e.g. C with 5 bonds) |
| No radicals | Even bond count for C, N, O, H | Highly reactive species unlikely to be isolable |

Bond cutoff per pair: `r_i + r_j + 0.40 Å` (covalent radii + tolerance for
ionic/metallic bonds). Minimum bond distance: 0.5 Å (below this, atoms are
considered overlapping rather than bonded).

## Files Description

### `structure_checks.py`
Pure validation logic — no MPI, no ADIOS, no I/O. Safe to import anywhere
(notebooks, unit tests, standalone scripts).

**Public API:**
```python
from structure_checks import check_stage1, check_stage2

# Stage 1: physical validity
passed, reason, min_d = check_stage1(
    cx, cy, cz,           # coordinate arrays (Å)
    fx, fy, fz,           # force arrays (eV/Å)
    energy,               # formation energy scalar (eV)
    N,                    # atom count
    energy_lo=-20.0,
    energy_hi=20.0,
    max_force=50.0,
    min_dist=0.5,
    do_mindist=True,
)

# Stage 2: synthesizability (call only if Stage 1 passed)
passed, reason = check_stage2(cx, cy, cz, atom_types, N)
```

**Exported tables** (importable directly):
```python
from structure_checks import COVALENT_RADII, MAX_VALENCE, SYNTHESIZABLE_Z
```

### `validate_structures.py`
MPI driver. Assigns tar files round-robin across ranks, extracts each to
`/tmp`, validates all structures via `structure_checks`, writes per-rank
`.npz` to Lustre, then reduces a global summary to rank 0.

```bash
# No MPI (testing)
python validate_structures.py \
    --tar_dir /path/to/tars \
    --out_dir ./results \
    --max_structs 100 \
    --verbose

# Full MPI run
srun -n 1280 python validate_structures.py \
    --tar_dir /lustre/orion/lrn070/.../tars \
    --out_dir /lustre/orion/lrn070/.../results
```

**CLI flags:**

| Flag | Default | Description |
|---|---|---|
| `--tar_dir` | required | Directory containing `*.tar` files |
| `--tar_pattern` | `*.tar` | Glob pattern for tar files |
| `--tmp_dir` | `/tmp` | Node-local extraction directory |
| `--out_dir` | required | Output directory for `.npz` files |
| `--min_dist` | `0.5` | Min interatomic distance (Å) |
| `--max_force` | `50.0` | Max force magnitude (eV/Å) |
| `--energy_lo` | `-20.0` | Min formation energy (eV) |
| `--energy_hi` | `20.0` | Max formation energy (eV) |
| `--max_structs` | `0` (all) | Cap per file, for testing |
| `--no_mindist` | off | Skip min-distance check |
| `--no_synth` | off | Skip Stage 2 checks |
| `--verbose` | off | Print per-file progress |

### `submit_validate.sh`
SLURM script for Andes. Configured for 40 nodes × 32 cores = 1,280 ranks,
6-hour walltime. Edit `TAR_DIR`, `OUT_DIR`, and the venv path before submitting.

```bash
sbatch submit_validate.sh
```

### `aggregate_validation.py`
Combines all per-rank `.npz` files after the job completes. Prints a global
summary with percentile distributions for min-distance and energy/atom.
Optional `--plot` flag generates histograms.

```bash
python aggregate_validation.py \
    --out_dir /path/to/results \
    --plot \
    --plot_out validation_summary.png
```

## Per-rank Output Format

Each rank writes `validation_rank{RANK:05d}.npz` containing:

| Key | Type | Description |
|---|---|---|
| `n_total` | int64 | Structures processed by this rank |
| `n_invalid` | int64 | Failed Stage 1 |
| `fail_energy` | int64 | Failed energy check |
| `fail_forces` | int64 | Failed force check |
| `fail_mindist` | int64 | Failed min-distance check |
| `n_synth_checked` | int64 | Reached Stage 2 |
| `n_synth_fail` | int64 | Failed Stage 2 |
| `fail_element` | int64 | Non-synthesizable element |
| `fail_isolated` | int64 | Isolated atom |
| `fail_valence` | int64 | Valence exceeded |
| `fail_radical` | int64 | Radical detected |
| `n_synthesizable` | int64 | Passed both stages |
| `bad_indices` | int64[] | Step indices of Stage 1 failures |
| `non_synth_indices` | int64[] | Step indices of Stage 2 failures |
| `min_dist_all` | float32[] | Min distance per structure (−1 if skipped) |
| `energies_per_atom` | float32[] | Energy/atom for Stage 1 survivors |
| `synth_energies_pa` | float32[] | Energy/atom for synthesizable structures |

## Planned Next Steps

- **Convex hull analysis** — compare formation energies against the Materials
  Project hull using `pymatgen`. Structures with energy above hull < 50–100 meV/atom
  are thermodynamically stable candidates.
- **Duplicate removal** — fingerprint-based deduplication (SOAP descriptors via
  `dscribe`, or RDF-based) and cross-reference against Materials Project / ICSD.
- **Structural analysis** — density, bond length distributions, coordination
  number histograms per element.
- **ML synthesizability scoring** — apply a dedicated synthesizability predictor
  (e.g. Davariashtiyani et al.) trained on ICSD for kinetic synthesizability.

## Key Design Decisions

**Why one rank per tar file?**
ADIOS2 BP5 steps must be read sequentially (BeginStep → EndStep). There is no
way to parallelize reads within a single BP5 file across multiple ranks. The
natural unit of parallelism is the file.

**Why extract to /tmp?**
Step-by-step ADIOS reads generate many small random-access I/O operations.
On Lustre this creates metadata pressure and is slow. Node-local `/tmp`
(NVMe on Andes) is orders of magnitude faster for this access pattern.
Each rank uses a unique subdirectory (`validate_rank{RANK}_{file_idx}/`) to
avoid collisions between the 32 ranks sharing each node. The directory is
deleted immediately after validation to keep `/tmp` from filling up.

**Why not `pip install adios2` on Andes/Frontier?**
The PyPI wheel is built without MPI support. On a cluster you need the system
`module load adios2` which is built against the Cray/OpenMPI stack and Lustre
transport. The pip wheel will load without error but silently do independent
(non-collective) I/O, which is ~50× slower on Lustre at scale.
